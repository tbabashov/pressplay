# Anti-Vibe-Coded Web Design

## Core directive

Do not behave like a website generator. Do not assemble popular UI patterns into the default AI formula:

> Navbar → hero → subtitle → CTA → three cards → feature section → testimonials → pricing → FAQ → footer

That structure is forbidden unless the product genuinely requires each section and there's a specific reason for it. The goal isn't "looks modern" — it's "someone had an unusually good idea." Every site should feel like a designer, product thinker, art director, and developer all deeply understood *this specific product* — not like it could be regenerated by swapping the logo and copy.

**The bar is not "good design." The bar is a physical reaction.** Someone should land on this page, pause, and go "wait — how did they even build this?" before they've read a single word. If the honest reaction to the finished page is "yeah, that's nice, clean, professional" — that is a failure state, not a milestone. Nice and clean is the AI-default. The target is *mesmerizing*: the page should feel alive, dense with intention, slightly disorienting in a good way, and genuinely hard to reverse-engineer at a glance.

## The primary test (run this constantly)

- **Could this design exist with a different product name, logo, and copy unchanged?** If yes → too generic.
- **Could I hand this exact design to another AI for a totally different company?** If yes → too generic.
- **Does the site contain several ideas clearly derived from THIS product**, not from web-design conventions? If no → redesign.
- **Would a person screenshot this and send it to a friend just because of how it looks or moves?** If no → it's not there yet.
- **Does the landing page have at least one moment that could NOT have come from a template library, a Dribbble scroll, or a "make it look premium" prompt?** If no → invent one before writing any more code.

The website must be product-shaped, not template-shaped — and it must be memorable enough that describing it later is easy ("the one where the map dissolves into the invoice," "the one where scrolling rewinds the timeline").

## Process: don't start with the landing page

Before writing any component, work through:

**Product** — What does it actually do? What's different about it? What's its central action or metaphor? What does a successful user do?

**User** — Who are they, what do they already know/expect, what would delight or annoy them, what builds trust?

**Emotional target** — Pick a deliberate character (precise, editorial, playful, obsessive, cinematic, mechanical, archival, luxurious, academic, rebellious, calm, eccentric, utilitarian, nostalgic, tactile, strange, futuristic-but-tactile, ceremonial...). Do NOT default to "clean, modern, minimal" — that phrase is now meaningless.

**Native metaphor** — What does the product naturally resemble? Instrument, workshop, archive, map, newspaper, laboratory, studio, library, control room, notebook, catalog, gallery, ledger, cockpit, field guide, blueprint, scorecard, museum, index. Don't force one where none exists; if one exists, exploit it deeply.

## Invent a central design concept

Not just a palette — the conceptual mechanism that gives the site its identity. Examples (don't copy — invent one for the actual product):

- **Music platform**: interface behaves like a record-sleeve archive; artwork influences the surrounding composition; scrubbing a track changes visual rhythm.
- **Weather product**: the page is a living atmospheric instrument — time, pressure, wind alter the composition.
- **Finance product**: numbers treated like an editorial financial newspaper with typographic choreography of historical movement.
- **Architecture portfolio**: projects presented as a navigable building; moving through the site feels like moving through rooms.
- **Recipe app**: ingredients become the primary navigation; selecting one reorganizes the recipe universe around it.

## Mesmerizing / futuristic mode (default target, not an add-on)

Unless the product's emotional target genuinely calls for restraint (e.g. a legal ledger, a medical form), treat "extremely modern, futuristic, almost impossible to have hand-coded" as the default bar for landing pages, not an optional flourish. This means:

- **Depth over flatness.** Layer the page: background field (subtle motion, particles, gradient mesh, grain, noise, parallax layers), a mid-ground of real content, and foreground accents that react to cursor/scroll/time. Flat single-plane sections read as templated by default.
- **The page should feel like it's *running*, not just displaying.** Something should always be quietly alive — a cursor-reactive field, a live-updating number, a shader-like background, an element that drifts, a data visualization that breathes. Nothing should feel static the instant it loads.
- **Motion is choreography, not decoration.** Scroll-linked transforms (pinning, scrubbing, morphing one section into the next), staggered reveals with real timing curves, elements that transform rather than fade, cursor-following elements, magnetic buttons, text that reflows or splits and reassembles. Every animation should look intentionally timed, not "add transition: all 0.3s to everything."
- **At least one "how" moment.** Something a viewer cannot immediately explain — a custom cursor that changes the scene, a section that only reveals itself through interaction, a 3D/WebGL-feeling element (can be faked convincingly with CSS transforms, SVG filters, and canvas — doesn't require a real 3D engine), a live generative pattern seeded by real data, a transition where one section visually becomes the next instead of cutting.
- **Precision over noise.** Futuristic does not mean cluttered. The mesmerizing effect comes from restraint plus one or two extremely well-executed signature mechanics, not from stacking every trend at once. Pick 2-4 signature moments and execute them at a level that looks expensive; do not spread the same effort thin across ten mediocre effects.
- **Typography and layout should do work most sites don't bother with**: variable-feeling type scales, kinetic typography tied to scroll/cursor, asymmetric grids that still feel controlled, intentional breaking of the grid at key moments.
- **Sound is optional and off by default**, but if the product supports it, a toggleable ambient/interaction sound layer is a legitimate signature moment — never autoplay audio.

This mode does not replace the "Forbidden default habits" list below — a futuristic, mesmerizing site built from glassmorphism + purple glow + sparkle icons is still a cliché. The wow-factor has to come from an invented mechanic, not from stacking trend-ingredients.

## Signature moments

Every site needs 1–4 **signature moments**: an interaction or visual behavior users are unlikely to find elsewhere — an unusual nav behavior, a live product demo, a spatial transition, a reactive data visualization, a novel information hierarchy. Must be specific + memorable + useful/delightful. Don't add gimmicks just to check this box — but for landing pages, treat "having zero signature moments" as a bug, not a safe default.

**The "thing" test**: complete "*The thing this website does that makes people remember it is ___.*" If the answer is "the animations," "the gradient," "the glass effect," or "the smooth scrolling" — insufficient. Good answers name a capability: "lets you physically rearrange the evidence behind every recommendation," "the homepage is itself a working version of the product," "scrolling down is scrubbing backward through the company's history in real time."

## Prove the product, don't describe it

Whenever feasible, **show it**: if interactive, make the homepage interactive; if it analyzes, show a live analysis; if it compares, let the user compare; if it transforms content, demonstrate the transformation. Build the smallest *real* version of the product that can be experienced immediately, without signup/modal/pricing friction. A fake dashboard screenshot or decorative UI illustration is not a demo.

Never fake functionality — no fake login success, fake uploads, fake search results, fake AI generation. Either implement it or clearly label it as a prototype/demo with sample data.

## Image, video, and GIF placeholders (mandatory system)

This environment cannot browse for or generate real photography, footage, or original illustration. Never invent a fake image URL, never link to a stock-photo site as if it will resolve, and never leave a blank/broken `<img>` tag. Instead, every visual asset slot must be a clearly marked, styled placeholder that:

1. **Occupies the real, final layout space** — correct aspect ratio, correct crop, correct position in the composition — so the page's structure and rhythm are already correct once real assets drop in.
2. **Is visually styled, not a gray box** — give it a tasteful background treatment (gradient, pattern, tone matching the palette) so the page still looks intentional and presentable before assets are added, not broken.
3. **Contains a clear, specific asset brief inside or attached to the placeholder**, describing exactly what should go there so the user (or a stock-photo/video search, or a generation tool) can source or produce the right thing. The brief should specify:
   - **Type**: photo / looping video / GIF / illustration / icon set / 3D render.
   - **Subject and framing**: what's in frame, composition, angle, crop (e.g. "close-up of hands typing on a mechanical keyboard, shallow depth of field, warm side light, shot from above at 45°").
   - **Mood/style**: matches the site's emotional target (e.g. "cinematic, desaturated, slightly grainy" vs "bright, high-key, editorial").
   - **Motion notes if video/GIF**: loopable or not, duration, what moves and what stays still.
   - **Dimensions/aspect ratio** for the slot.

   Example inline placeholder pattern (adapt visually to the site, don't literally reuse this styling everywhere):
   ```html
   <div class="asset-placeholder" style="aspect-ratio: 16/9;">
     <span class="asset-placeholder__label">IMAGE PLACEHOLDER</span>
     <p class="asset-placeholder__brief">
       Photo — overhead shot of a busy editorial desk: scattered proof pages,
       a red pen, a coffee ring stain. Warm tungsten light, slightly desaturated,
       documentary feel. No people visible. 16:9.
     </p>
   </div>
   ```
   For video/GIF slots, label it `VIDEO PLACEHOLDER` or `GIF PLACEHOLDER` and describe the motion, not just the still frame.
4. **Never substitutes generic decorative stock-photo energy for the signature moments above.** Placeholders are for genuinely photographic/video content (team photos, product-in-use shots, editorial imagery, background footage). Interactive/generative visual elements (data viz, custom cursors, shader-like backgrounds, animated diagrams) should still be actually built, not placeholder-briefed — those are code, not assets.
5. Keep a running mental (or commented, at the top of the file) inventory of every placeholder on the page so nothing gets dropped silently — if asked, be able to list every asset slot and its brief in one place.

## Forbidden default habits

Only use these if there's a genuine product-specific reason:

- **Harsh decorative gradients** (purple→blue, pink→orange, rainbow) — use gradients as material/atmosphere/data, not decoration.
- **Lucide/generic icon libraries** as default visual language — use custom marks, typography, or real imagery instead; don't fill space with icons.
- **Pure `#FFFFFF` backgrounds** — but also don't just swap to "AI beige"; the surface should belong to the concept.
- **Rainbow/unrelated accent colors** — establish a controlled vocabulary where color = meaning.
- **Generic floating-card drop shadows** — prefer borders, contrast, layering, real spatial depth.
- **Three feature cards in a row** — one of the clearest template tells. Use sequential storytelling, comparison, timeline, spatial map, or one big idea with detail instead.
- **Emojis as UI decoration** (🚀✨🔥💡⚡) unless the product literally revolves around them.
- **Glassmorphism / backdrop blur / glowing borders** as a substitute for identity.
- **Em dashes in copy.**
- **Default fonts** (Inter, Geist, Space Grotesk) picked out of habit rather than intent.
- **Colored left-stripe** feature rows.
- **Fabricated testimonials, logos, ratings, or customer quotes.** If real ones aren't available, ship without that section.
- **Bento grids** as a synonym for "creative."
- **Fake terminal windows** unless the terminal is genuinely part of the product.
- **"It's not X. It's Y." copy formula.**
- **Checkmark bullet lists** ("✓ Fast ✓ Secure ✓ Powerful") — show evidence instead of adjectives.
- **Three pricing tiers** by default — reflect the actual business model (usage-based, one plan, calculator, custom quote). Never fabricate pricing that doesn't exist.
- **Uniform `border-radius: 24px` everywhere** — mix sharp, subtle, circular, cropped geometry with intent.
- **Black + purple glow "AI futuristic"** palette — this is the single most overused shortcut to fake "futuristic." Real futuristic comes from mechanic + motion + precision, not this specific palette.
- **Missing loading/empty/error states** — build real ones.
- **Radial glow orbs, dot-grid backgrounds, sparkle icons** as decorative atmosphere.
- **Animated bouncing arrows** to signal "click here."
- **Generic hover kit** (scale 1.02, translateY(-4px), shadow bump) applied uniformly — hover should communicate *what* changed, not just "this is clickable."
- **Missing legal pages** for a real product (ToS, privacy) — create real routes, never fabricate compliance claims.
- **Broken or blank image tags** — every asset slot must use the placeholder system above, never a dead `<img>` or a lorem-picsum-style filler with no brief.

**Do not replace one cliché with another** — "purple is banned so use orange," "bento is banned so use brutalist cards," "rounded is banned so go sharp," "add particles because that's the new futuristic-signal" all just create a new template. The goal is specificity, not anti-trend. A mesmerizing site earns its wow-factor from an invented mechanic executed precisely — not from importing a generic "futuristic effects" starter kit.

## Information architecture follows user intent

Don't organize around what marketing sites traditionally contain — organize around what the user needs to understand or do next:

- Demonstration-first: see → manipulate → understand → trust → act
- Narrative-first: question → tension → discovery → proof → action
- Tool-first: input → transformation → result → explanation → upgrade
- Exploration-first: browse → filter → discover → inspect → save
- Product-led: use → encounter capability → understand value → continue

## The hero isn't sacred

Alternatives to giant-centered-headline-plus-CTA: immediate interaction with the real product; a striking visual artifact; a question posed by the interface; live real data; a before/after; starting mid-narrative; a full-screen tool that's already open; an ambient scene the user's cursor disturbs before any text even appears.

## Product-specific interactions

Build interactions that only make sense for this product: scrubbing across time/price/history/versions; layer toggling to reveal evidence/metadata/context; rearranging/ranking/filtering/composing; input→process→output transformation views. Every interaction must communicate something — cause and effect (change input → visualization updates) is one of the strongest ways to make software feel intelligent.

**Micro-systems** > random animations: a timeline system where time is the navigational concept; a confidence system that visually expresses certainty; a provenance system where info traces to its source; a material system where content types have distinct visual materials.

## Motion, scroll, and typography

- Animate only with purpose: continuity, causality, hierarchy, transformation, feedback. Not "sections fade in because websites need animation" — but on landing pages, absence of any purposeful motion is itself a tell of a rushed build, so budget for it deliberately.
- Scroll can zoom, reveal, transform, traverse space, or change product state — not just "section appears, section appears."
- Typography is a primary design element: design scale, rhythm, line length, density, tracking — not just "pick font, 48px heading, done." Large type is a tool, not a personality.
- Layout needs rhythm: dense/sparse areas, full bleed, asymmetry, interruptions — not identical repeating section/padding/container/cards blocks.
- Performance budget still applies to heavy motion: prefer CSS transforms/opacity and canvas/SVG over layout-thrashing JS; test that scroll stays smooth with the signature moments in place. A mesmerizing page that stutters is worse than a calmer page that's buttery.

## Content and microcopy

Avoid vague AI marketing language: "Unlock your potential," "The future of...," "Revolutionize your workflow," "Seamlessly transform," "Built for the modern...," "Work smarter, not harder," "Your all-in-one solution," "Supercharge your..." These carry no product information — replace with concrete claims, specific numbers, observable behavior.

Buttons should describe actions, not generic CTAs: "Analyze this file," "Compare versions," "Open the archive" — not "Get Started" / "Learn More" / "Explore."

Show evidence instead of claims: "0.18s" with a real interaction beats "Lightning-fast search." Never fabricate metrics, user counts, or activity.

## Real data, real states

- Never fabricate testimonials, logos, reviews, or metrics. A truthful empty section beats fake credibility.
- Empty states should teach or demonstrate, not just say "Nothing here yet."
- Error states should say what happened, why, and what to do — not a generic decorative message.
- Loading states should reflect the product's actual concept (stages of analysis, progressive discovery) where possible, not a bare spinner or "Loading...".

## Responsive design

Rethink for mobile, don't just shrink desktop. Decide what disappears, what becomes primary, what becomes a drawer or gesture. Mobile can have its own gimmick (swipe comparison, long-press inspection) instead of forcing desktop metaphors down. Heavy cursor-driven signature moments need a real mobile equivalent (touch/scroll-driven), not a silently disabled feature.

## Accessibility and performance are not optional

Keyboard navigation, focus states, semantic HTML, contrast, reduced-motion (`prefers-reduced-motion` must meaningfully simplify the heavy animation, not just shave a few milliseconds), touch targets must survive the creative direction. Avoid unnecessary heavy libraries/WebGL/blur that hurt load time — technology doesn't create creativity by itself; it must serve a meaningful experience. Ambition and performance are not in tension if the signature moments are chosen carefully (2-4, well-executed) instead of maximized (everything, all at once, janky).

## Self-check tests to run before shipping

- **Why does this exist?** For every visual element. Good answers: communicates hierarchy, explains the product, demonstrates functionality, creates navigation, delivers the wow-moment. Bad answers: "looks cool," "websites usually have this," "the section looked empty" → delete it.
- **Could I remove this and make it clearer?** If yes, remove it.
- **Would a human designer explain this choice?** If the only answer is aesthetic preference, reconsider.
- **The "remove 30%" pass**: after v1, strip ~30% of decorative elements (redundant borders, filler icons, repetitive animation, filler copy) and reassess — this applies even in mesmerizing mode; wow-factor comes from precision, not accumulation.
- **Anti-template test**: imagine swapping product name/logo/copy/colors for a different company. If the design still works fine → fail. If it becomes nonsensical → pass.
- **The "dayum" test**: picture a stranger's first three seconds on the page. Is there a specific, nameable reason they'd react rather than just scroll past? If the honest answer is "it looks nice" → not enough. Name the mechanic.
- **The placeholder audit**: every non-generative visual asset slot (photo/video/GIF) has a real, specific brief attached — none are blank, broken, or vaguely labeled "image here."

## Category-specific guidance

- **AI products**: no sparkle icons, purple glow, black background, "AI-powered/intelligent/magic" copy, or generic chatbot UI. Instead show input → process → transformation → output, with control, sources, and iteration made visible.
- **SaaS**: skip hero/logo-wall/features/testimonials/pricing/FAQ by default. Prioritize real product interaction, workflow, before/after, actual use cases.
- **Portfolio**: don't default to hero/about/3 projects/skills/testimonials/contact. Let the work determine structure — visual archive, project timeline, case-study journey.
- **Content-heavy sites**: prioritize reading rhythm, typography, search, and context — don't turn every paragraph into a card.
- **Data-heavy sites**: prioritize accuracy, density, filtering, drill-down over making it look like a sci-fi movie interface (unless the product is literally about instrumentation, in which case lean in — see Mesmerizing mode).
- **"Boring" products**: find the interesting behavioral core instead of compensating with gradients — e.g. a file manager can become a provenance/relationship explorer; a form can become a guided sequence that explains each input.
- **Marketplaces / multi-vendor sites**: the browsing/discovery mechanic itself is the best candidate for a signature moment (how listings are filtered, compared, previewed) — don't bury it under a generic card grid.

## The three-round process

1. **Concept** — product behavior, user, design thesis, metaphor, visual language, signature interaction(s), information architecture, and (for landing pages) the specific mesmerizing mechanic. Don't polish yet.
2. **Experience** — real interactions, product demo, states, responsive behavior, navigation, hierarchy, motion choreography. Should be interesting even unpolished.
3. **Art direction** — typography, spacing, composition, imagery (with placeholder briefs where real assets are needed), motion, micro-interactions, details. Only now add subtle decoration where it genuinely helps.

## Before writing code, write a short design thesis

> This website feels like ___ because ___.
> The main interaction is ___ because ___.
> The visual language is based on ___.
> The user should remember ___.
> The signature moment is ___.
> The "how did you build this" moment is ___ (name the specific mechanic — cursor-reactive field, scroll-scrubbed transformation, live data choreography, etc.)

Also write a **"do not become this" list** — 5–10 obvious failure modes to actively design away from (e.g. "generic SaaS," "dashboard template," "bento showcase," "crypto landing page," "black+purple AI glow deck," "stock-photo hero with a gradient overlay and a bold headline").

## Final quality bar

A finished site should feel intentional rather than assembled, specific rather than generic, authored rather than generated, interactive rather than decorative, memorable rather than merely attractive, and — for landing pages especially — genuinely mesmerizing rather than just polished. Before shipping, ask: **if the user remembers only one thing about this site tomorrow, what will it be — and did we deliberately design that memory?** If not, keep working. A polished, responsive, smooth-animated site is table stakes, not the goal. The goal: **the website could only have been designed for this product, and someone looking at it should have a hard time believing it wasn't hand-built by a specialist studio.**
